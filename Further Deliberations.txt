Ch 24 - Function Template
Blueprint to generate function - based on input arguments
Helps with writing less repeatative function overloads

Declaration: 
template <typename T>
T function(T var_a, T var_b);

Definition:
template <typename T>
T function(T var_a, T var_b){
    ..;
}

Type specific function call - Template type
- allows template to be different type than input, enforces implicit conversion
function<Type>(input arg);

Pass by reference
Declaration:
template <typename T>
const T& function(const T& var_a, const T& var_b);

Definition:
template <typename T>
const T& function(const T& var_a, const T& var_b){
    a..b..;
}

- Cannot have both pass by value and pass by reference templates defined

- Template vs Overload priority:
1 Raw Overload
2 Closest template type T match
3 Generic template type T match

Template Specialization - add specialization overload

Definition:
[return type] function<[template argument specific type]>(input type a, input type b){
    a..b..;
}

Ch 25 Concepts - constraints on template function

#include concepts
- Template would work only if requirement is fulfilled
- set constraints on template type parameters
- concepts can be type and also type traits (std::is_[type])
- keyword: requires

Concept declaration 4 syntaxes:

After Template Declaration:
template <typename T> 
requires std::[type]<T>
T function(T var_a, T var_b){
    a..b..;
}

In Template Declaration:
template <std::[type] T>
T function(T var_a, T var_b){
    a..b..;
}

In parameter list:
template <typename T> 
std::[type] auto function(auto std::[type] var_a, auto std::[type] var_b){
    a..b..;
}

After parameter list:
template <typename T> 
T function(T var_a, T var_b) requires std::[type]<T>{
    a..b..;
}

Custom concept
- Type trait requirement
- Allows custom action of input parameter to determine a concept

template <typename T> 
concept [custom_concept] = std::[is_type_trait]<T>;

- Argument operation type requirement
- checks for type syntax, not actual operation
template <typename T> 
concept [custom_concept] = requires (T a, T b){
    arg..action();
}

- then usage is same
template <typename T> 
requires [custom_concept]<T>

Nested requirement
- Argument operation evaluation requirement 
template <typename T> 
concept [custom_concept] = requires (arg list){
    arg..action();
    requires arg..action();     // evaluates the action for true
}

Ch 36 Inheritence
note: By Inheritence we can only make the derived class constrained, not relaxed

define [base class]
class [base_class];   // forward declaration?

class [derived_class]: [Inheritence_Contstraint] [base_class]{
};

[Inheritence_Contstraint] = public|protected|private

friend class/function
- has access to private members of derived class
- no access to base class

public Inheritence - derived class will have access to public and protected members
(no change in derived class member access design)
public -> public
protected -> protected
private -> private

protected Inheritence - derived class will have access to public and protected members?
public -> protected
protected -> protected
private -> private

private Inheritence - derived class will have no access to base class members
public -> private
protected -> private
private -> private

Base Class  |   public Inheritence  | protected Inheritence |   private Inheritence
-----------------------------------------------------------------------------------
public      |   public              |   protected           |   private
protected   |   protected           |   protected           |   private
private     |   private             |   private             |   private

class           |   public              |   protected               |   private
access          |   object/external     |   only class function     |   only class function
inheritence     |   object/external     |   only class function     |   only base class function
